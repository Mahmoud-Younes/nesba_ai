# AGENTS.md

Nesba (نسبة) — Arabic-first Flutter nutrition assistant, graduation capstone, Android is the primary platform.
The app is still the Flutter counter template: `lib/` has only the entrypoints, `test/` is empty, and the stack
proposed in the discovery docs (Dio, go_router, Firebase AI Logic, Firestore) is **not** in `pubspec.yaml` yet.

## Commands

- Run dev: `flutter run --flavor development --target lib/main_development.dart` (prod: `lib/main_production.dart`, `--flavor production`).
- Flavors exist only for Android (`android/app/build.gradle.kts`; `development` adds `.dev`). iOS/web/windows build without `--flavor`.
- `flutter analyze` — currently clean; `analysis_options.yaml` is `flutter_lints` and excludes platform dirs.
- `flutter test` — no tests, no fixtures, no test helper exist yet.
- What CI does on push to `main` (Firebase App Distribution):
  `cd android && bundle install && bundle exec fastlane android firebase_distribution` — needs `FIREBASE_CLI_TOKEN` and `FIREBASE_APP_ID`.
  The lane hardcodes the tester email and release notes in `android/fastlane/Fastfile`.
- `flutter build apk --release` is signed with the debug keys (`android/app/build.gradle.kts` release block is still a TODO) — fine for Firebase test distributions, not for shipping.
- After editing discovery docs: `python files/discovery/tools/check_discovery.py files/discovery/docs/discovery`
  must print `no structural problems found` (the docs say `python3` and `docs/discovery`; the real paths are under `files/discovery/`).

## Layout

- Entrypoints are `lib/main_development.dart` and `lib/main_production.dart`; `main.dart` does not exist.
- `lib/firebase_options.dart` and `android/app/google-services.json` are generated by the FlutterFire CLI for project
  `nesba-5a3fb` — regenerate with `flutterfire configure`, do not hand-edit.
- Platforms: android, ios, web, windows. `macos/` and `linux/` were deleted on purpose; do not restore them.
- `files/` is planning docs only, not shipped code.

## Read before building features

- `files/discovery/docs/discovery/AI_CONTEXT.md` first — it is the one-page hub with a "Where to look"
  table; open the one doc it names instead of all 13. `[U]` and `[T]` tags are unknown, never facts; anything not
  marked Decided is Proposed, and the team has not approved the stack yet.
- `files/ui-ux/README.md` — UI is Arabic-first native RTL: `start`/`end` never left/right, Latin digits, metric units,
  tokens from `suggestion_design.md` (no hex values in widgets), over-goal state is apricot and calm, never red.

## Rules that bite

- Never claim Nesba is the first (or the only) Arabic AI food tracker; never give medical, treatment, or
  allergen-safety advice; never put a secret in the APK; strip names/emails before sending text to any AI model.
- Numbers shown to users are computed in Dart from reference data; the model may only return structured items.
- `.opencode/skills/` defines the enforced UI conventions (theme constants in `lib/core/theme/`, `flutter_gen`
  assets, ARB localization, Figma assets reused from disk). Those paths do not exist yet — follow the skill to
  create them on the first UI change rather than inlining colors or strings "for now".
- Git: branches `type/ID-name` (`feat/FR-21-parse-schema`), Conventional Commits with `Refs: FR-xx` in the body,
  one requirement per PR (~400 changed lines max), squash merge with a Conventional Commit PR title, PRs list
  requirement IDs and disclose AI assistance (GIT-02/03/04/05/08 in `07-WORKPLAN.md`).
